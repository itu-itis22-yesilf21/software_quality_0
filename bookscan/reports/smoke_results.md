## Sample input (shared by all four runs)

```
The cat sat on the mat
On the MAT was a rat
the dog ran
A cat chased the mouse
the the the
```

Target word length = 3.

## Integration output per variant

### `llm_a/unmodified` — GPT-5.5

```text
scanWords(text, 3) -> {The=count=1, lines=[1], cat=count=2, lines=[1, 4],
                       sat=count=1, lines=[1], the=count=7, lines=[1, 2, 3, 4, 5],
                       mat=count=1, lines=[1], MAT=count=1, lines=[2],
                       was=count=1, lines=[2], rat=count=1, lines=[2],
                       dog=count=1, lines=[3], ran=count=1, lines=[3]}
```

What this reveals:

- **Case-sensitive on purpose, accidentally.** `The` / `the` and
  `MAT` / `mat` appear as separate keys because the model's
  "normalisation" step is `flipCase(flipCase(x))`, which is the
  identity function. The model called `flipCase` but never folded
  case.
- **Two parallel counting paths.** The `count=7` for `the` comes from
  the second-pass `howManyTimes` over a synthesised " "-separated
  stream of all length-3 words; `lines=[1,2,3,4,5]` comes from the
  earlier `lines.contains(n) ? skip : add` loop, so line numbers are
  deduplicated even though counts are not.

### `llm_b/unmodified` — Gemini 3.1 Pro

```text
scanWordsOfLength(text, 3) -> {the=Count: 7, Lines: [1, 2, 3, 4, 5],
                                mat=Count: 2, Lines: [1, 2],
                                rat=Count: 1, Lines: [2],
                                cat=Count: 2, Lines: [1, 4],
                                sat=Count: 1, Lines: [1],
                                was=Count: 1, Lines: [2],
                                dog=Count: 1, Lines: [3],
                                ran=Count: 1, Lines: [3]}
```

What this reveals:

- **Case is folded for the *key* but matched literally.** Gemini
  lowercases the key (`word.toLowerCase()`) and then counts
  `howManyTimes(line, word) + howManyTimes(line, flipCase(word))` —
  i.e., the all-lowercase and the all-uppercase variants only. The
  text's "The" on line 1 contributes **0** to `the=Count`. The
  expected count for `the` if MixedCase were honoured is 8
  ("The" + "the" on line 1, then 1+1+1+3 on lines 2–5). The
  observed `Count: 7` confirms the MixedCase miss.
- **Substring-of-longer-word false positives latent.** None show on
  this 5-line sample because all length-3 words happen to be whole
  tokens, but the implementation would mis-count `"cat"` inside
  `"concatenate"`. The Step 9 ECP/BVA test will trigger this case.

### `llm_a/edited` — GPT-5.5

```text
scan(lines, 3) -> {the=[1, 1, 2, 3, 4, 5, 5, 5], cat=[1, 4], sat=[1],
                    mat=[1, 2], was=[2], rat=[2], dog=[3], ran=[3]}
```

- Per-occurrence repetition (`the` appears 2× on line 1 and 3× on
  line 5, so the list contains 8 entries in ascending order).
- `MAT` collapses into `mat=[1, 2]` via real `flipCase`-based
  normalisation.
- Output type matches the Variant 2 spec: `Map<String, List<Integer>>`,
  insertion order via `LinkedHashMap`.

### `llm_b/edited` — Gemini 3.1 Pro

```text
scan(lines, 3) -> {the=[1, 1, 2, 3, 4, 5, 5, 5], mat=[1, 2], rat=[2],
                    cat=[1, 4], sat=[1], was=[2], dog=[3], ran=[3]}
```

- Same map *contents* as `llm_a/edited`, character-for-character.
- Different *iteration order* because Gemini chose `HashMap` instead
  of `LinkedHashMap`. The spec explicitly allowed this
  ("key order does not matter"), so it is not a bug; it is logged
  here as the only observable difference between the two edited
  variants under this 5-line input.

## What Step 4 leaves for later steps

- **Step 5 (integration tests)** will author one integration suite per
  variant. The two unmodified variants need bespoke suites because
  their public APIs and counting semantics differ from the spec; the
  two edited variants will share a single suite written against the
  Variant 2 contract.
- **Step 7 (coverage)** will measure the per-variant branch coverage
  reached by the Step 5 suites, mirroring Phase 1's JaCoCo workflow.
- **Step 9 (ECP/BVA)** will trigger the latent MixedCase miss and
  substring-of-longer-word false-positive that the smoke run did
  not surface.

Re-run any time with `python bookscan/run_smoke.py`. Class files are
gitignored.
